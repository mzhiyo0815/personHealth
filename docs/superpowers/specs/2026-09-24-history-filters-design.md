# 历史记录组合筛选设计

## 目标

让长期使用者能在手机上快速找到过去的健康记录，同时保持当前按日期分组、按天分页和账号隔离行为。首版提供日期范围、记录类型与关键词组合筛选，不增加数据表或外部搜索服务。

## 范围

历史页筛选栏包含：

- 开始日期与结束日期，均可留空；日期按 `Asia/Shanghai` 本地日界解释，范围两端都包含。
- 记录类型：全部、饮食、运动、体重、腰围。
- 关键词：去除首尾空白后，对饮食的食物名称、份量/备注，以及运动备注做不区分大小写的包含搜索。身体指标不参与关键词匹配。
- “筛选”与“清除筛选”操作；清除后回到未筛选的历史页。

不包含模糊分词、营养数值搜索、力量动作名称搜索、保存筛选条件或数据导入。

## 查询与数据流

新增一个普通 Django 表单负责清理 GET 参数。视图先验证表单，再从当前用户的 `meals`、`exercises` 和 `measurements` 关联管理器分别建立查询，绝不从全局模型管理器读取记录。

类型筛选决定需要查询哪些记录集合：体重和腰围使用各自的 `Measurement.kind` 条件。日期范围转换为本地时区的左闭右开时间区间；结束日期使用次日零点作为上界，避免遗漏当天晚间记录。关键词只应用于饮食和运动集合；当关键词与体重或腰围类型同时选择时，结果为空，而不是忽略关键词。

有效结果继续按本地日期分组、日期倒序分页，每页 7 个日期。分页链接使用清理后的有效筛选参数，并只替换 `page`，避免参数丢失或重复。

## 验证与错误处理

- 开始日期晚于结束日期时，在筛选栏显示“开始日期不能晚于结束日期。”，不查询或展示记录。
- 非法日期或未知类型使用字段级中文错误，不静默降级成全部记录。
- 关键词长度上限为 100 个字符；超长内容显示中文错误。
- `page` 非数字或越界继续采用 Django Paginator 的安全行为：非数字显示第一页，越界显示最后一页。
- 空结果显示“没有符合筛选条件的记录。”；完全未筛选且没有数据仍显示“暂无记录。”。

## 界面与可访问性

筛选控件使用服务端 HTML 表单和原生 GET 提交，无 JavaScript 依赖。手机端为单列排列，较宽屏幕可分栏；按钮保持至少 44px 点击高度。每个控件有明确中文标签，错误通过现有 `.errorlist` 样式展示。

页面在存在有效筛选时显示简短结果提示和“清除筛选”链接。上一页、下一页链接保留全部有效条件，并提供包含当前页与总页数的文本。

## 安全与隐私

- 所有数据查询必须从 `request.user` 的关联管理器开始。
- 搜索由 ORM 参数化查询完成，不拼接 SQL。
- 模板只回显表单清理后的值；无效输入由 Django 自动转义。
- 筛选参数不写入 localStorage，也不进入应用日志的自定义字段。

## 测试与验收

采用测试驱动开发，至少覆盖：

- 单独及组合使用日期范围、类型、关键词。
- 本地日界两端包含与相邻日期排除。
- 饮食字段和运动备注关键词匹配。
- 非法日期、反向范围、未知类型和超长关键词。
- 其他账号记录永不出现在结果中。
- 分页链接保留筛选条件且页码正确。
- 筛选空结果和完全无数据的不同文案。
- 360、390、430 与 1280px 无横向溢出，表单控件与操作区域满足触控尺寸。

## 非目标

本功能不改变记录模型、导出格式、趋势计算和今日页，不实现全文搜索、标签、排序切换或保存筛选方案。
