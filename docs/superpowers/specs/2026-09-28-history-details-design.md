# 历史记录详情设计

## 目标

历史页的每条记录可直接查看保存时填写的内容，无需进入编辑表单。保持当前日期分组、筛选、分页和账号隔离。

## 界面

- 现有摘要、编辑和删除入口保留。摘要下增加原生 `<details>`，按钮文案为“查看详情”。无 JavaScript 时也可展开。
- 饮食详情显示有值的份量/备注、饱腹感（1–10）、热量（千卡 kcal）、蛋白质/碳水化合物/脂肪（克 g）。零值属于已填写数据，必须显示。空字段不显示；若全部可选字段为空，显示“未填写其他信息”。
- 运动详情显示强度、非空备注和力量动作。动作按 `order` 顺序显示名称、组数、每组次数；负重有值时显示千克（kg），零负重也显示。非力量运动或无动作时不显示空的动作列表。
- 体重、腰围的摘要已包含全部业务信息，不额外增加展开区。
- 详情文字由 Django 模板默认转义；不渲染照片占位 URL。

## 数据与性能

历史视图继续从当前用户关联管理器取得数据。仅当前页运动记录需要力量动作，使用 `prefetch_related("strength_sets")`，避免展开多条记录时逐条查询。详情展示不增加新路由、不修改模型和导出。

## 验收

- 多条饮食与运动详情显示对应字段、单位和动作顺序；空字段隐藏、零值显示。
- 其他用户的记录及其动作不出现在页面。
- 查询数量随同页运动记录数保持稳定。
- 手机 360/390/430px 与桌面 1280px 无横向溢出，展开控件至少 44px 高。
